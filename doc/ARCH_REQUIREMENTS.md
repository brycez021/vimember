# vimember 架构规范要求

> 本文件约束 vimember 的架构演进。当前已进入首页原型阶段，已确认的产品决策必须进入后续实现，未确认的 Figma 与交互细节不得猜测。

## 1. 总体原则

1. 视频日记优先：核心数据单元是“视频 + 文字”。
2. 本地优先：当前需求未包含账号、云同步或后端服务。
3. Figma 优先：正式 UI 必须读取用户指定的 Figma 内容后再实现。
4. 不猜测：影响体验、数据安全、架构或视觉的未知点必须先问用户。
5. 小步可回滚：每次改动只处理一个明确目标。
6. 最低支持 iOS 17.0。

## 2. 核心模块边界

后续实现建议按以下职责划分：

1. `App`：应用入口、权限描述、根导航。
2. `Features/Import`：从系统相册导入视频。
3. `Features/Editor`：给视频添加或修改文字。
4. `Features/Home`：首页纵向视频日记列表。
5. `Features/Gallery`：画廊浏览。
6. `Features/Detail`：完整视频和文字详情。
7. `Domain`：视频日记模型、摘要规则、播放策略。
8. `Services`：相册访问、视频资源、缩略图、持久化。
9. `DesignSystem`：来自 Figma 的设计 Token 和组件。

实际目录可在创建 Xcode 工程时根据项目模板调整，但职责边界不可混乱。

## 3. 数据与持久化要求

已确认：

1. 视频导入后复制到 App 沙盒。
2. 文字保存到 App 本地数据库。
3. 本地数据库优先使用 SwiftData；如工程条件不适配，必须说明原因再更换方案。
4. 数据库记录保存本地视频路径、文字、摘要相关数据、创建/更新时间和原相册来源标识。
5. 摘要展示正文前面固定字数的一部分；具体字数、行数和截断样式后续确认。
6. 删除视频日记时，只删除 App 本地数据库记录和 App 沙盒视频文件。
7. 删除流程任何时候不得删除系统相册原视频。

必须满足：

1. 数据模型能稳定表示一条视频日记。
2. 数据读取失败时有明确降级状态。
3. 删除记录前必须二次确认。
4. 数据迁移策略在模型变化时必须可追踪。
5. 当前画廊页已有分类专辑栏视觉原型，但正式专辑数据模型、视频归属关系和创建流程仍待用户确认。

## 4. 相册与权限

1. 导入视频必须使用 iOS 公开 API。
2. 必须处理授权、拒绝、受限授权、用户取消和资源读取失败。
3. 不得使用私有 API 读取或写入系统相册元数据。
4. 权限说明文案必须和实际用途一致。
5. 导入后必须把视频复制到 App 沙盒，再进入编辑页。
6. 首页加号进入自定义视频选择页面，该页面必须按 Figma `选择视频` Frame 制作。
7. 视频选择页面中的视频缩略图一律裁剪成正方形展示。
8. 选中视频后点右上角对号必须先进入视频预览页，视频预览页必须按 Figma `添加-视频页` Frame 制作。
9. 视频预览页只播放当前选中的一条视频并自动播放。
10. 视频预览页不管横屏还是竖屏，视频都在屏幕中居中显示，并在上边缘和下边缘丝滑融入动态取色背景。
11. 视频预览页底部向下箭头进入添加文字页，添加文字页必须按 Figma `添加-文字页` Frame 制作。
12. 添加文字页背景色必须与视频预览页下方纯色背景一致，正文不设固定显示高度，超出屏幕后通过页面滚动查看。

## 5. 视频播放要求

### 首页

1. 滚动过程中视频不动。
2. 滚动停止后，当前屏幕中最主要的一条可见视频立即开始播放。
3. 同一时间只播放一条首页视频。
4. 离开屏幕的视频必须及时暂停并释放不必要资源。
5. 播放状态不能阻塞滚动流畅性。
6. “最主要的一条视频”的具体判定方式需要在实现前结合 Figma 和用户确认。
7. 首页必须按 Figma `首页` Frame 制作，并正确处理 Frame 中上下超出屏幕的内容和屏幕范围标识。
8. 首页布局必须适配不同尺寸 iPhone，避免使用固定画布尺寸硬编码关键位置。
9. 首页视频展示参考用户提供的“文稿/视频”demo 效果，demo 路径为 `/Users/zhangsiyuan/Documents/视频`；只参考效果，不参考 demo 实现方式，正式视觉以 Figma 为准。
10. 每个视频必须有动态取色纯色底；竖屏纯色底与视频同高，横屏纯色底高于视频并向下超出视频下边界。
11. 视频下方必须有从上到下逐渐增强的取色渐变和透明度处理，使视频与纯色底自然融合，不能出现清晰视频、融合层或纯色底之间的明显分界线。
12. 纯色底颜色需要从视频底部融合参考区域实时取色。
13. 首页文字结构为标题、日期、横线、正文；正文在首页最多显示两行。
14. 首页左下角跑道圆为搜索框入口，右下角圆形按钮为添加新内容入口，右上角圆形按钮为切换设置入口。
15. 切换设置卡片必须按 Figma `首页-切换` Frame 制作，包含日期显示方式切换和切换到画廊视图。
16. 日期显示方式切换规则待用户后续提供，不得提前猜测实现。
17. 横屏首页卡片已确认的 Figma 参考值：视频 `420pt * 236pt`，纯色底 `420pt * 322pt`，底色向下超出 `86pt`；当前实现通过清晰视频下边缘渐隐和窄范围动态取色渐变罩实现边缘化开并融入纯色底，不新增横屏封面/视频模糊层。
18. 竖屏首页卡片已确认的 Figma 参考值：视频约 `420pt * 745pt`，纯色底与视频同高，文字标题顶部约在视频底部上方 `114pt`。
19. 首页内容按时间倒序展示，最新视频在最上面；刚打开首页时，最上面视频卡片上边界与屏幕上边界对齐。
20. 首页文字层必须位于视频融合层之上，纯色渐变罩不得覆盖文字。
21. 当前首页横屏文字逻辑已按用户要求复制竖屏当前文字逻辑：标题、日期、横线、正文 top-from-bottom 基准分别为 `125pt`、`91.5pt`、`66pt`、`60.5pt`，整体偏移为 `0`。
22. 首页顶部和底部使用淡白色渐变模糊层柔化屏幕边缘。

### 详情页

1. 视频进入详情后自动播放。
2. 视频播放结束后循环播放。
3. 支持再次编辑文字，当前入口为右上跑道圆编辑按钮。
4. 支持删除视频日记，当前入口为右上圆形删除按钮，必须弹确认后再删除。
5. 删除只删除 App 本地数据库记录和 App 沙盒视频文件，不删除系统相册原视频。
6. 详情页文字卡片可从底部上滑展开为完整文字页，展开背景使用视频底部动态取色底色。
7. 横屏详情视频在屏幕中视觉居中，上边缘和下边缘都需要融入动态取色背景。
8. 退出详情页时必须正确暂停或释放播放器。
9. 后台、锁屏、来电、App 切换等生命周期需要明确处理。

### 画廊页

1. 画廊页必须按用户指定的 Figma `Frame 8`，节点 `158:550` 实现。
2. 顶部 `Albums` 专辑栏横向滚动；第一个圆为添加新专辑入口的视觉占位，当前不实现创建流程。
3. 专辑封面使用专辑内第一个视频的中间画面裁成圆形；在正式专辑模型确认前，只能作为视觉原型处理。
4. 当前不实现点击专辑进入专辑详情页。
5. `All Videos` 区域为三列视频卡片网格，支持纵向滚动查看更多。
6. 视频卡片使用中间帧缩略图和正方形居中裁切，不应让画廊同时播放大量视频。
7. 视频卡片下方垫动态取色纯色背景，并让缩略图底部丝滑融入背景。
8. 视频卡片标题最多两行，过长省略。
9. 视频卡片左右缝隙和上下缝隙必须一致；卡片圆角为 `3pt`，贴屏幕边缘的外侧角保持直角。

## 6. UI 与设计系统

1. 任何页面实现前必须读取用户指定的 Figma 节点。
2. 颜色、字体、间距、圆角、阴影、图标、布局比例必须来自 Figma 或用户确认。
3. 不得继承旧项目参考文件中的颜色和布局。
4. 首页、画廊、详情、导入、编辑的空状态和错误状态如果 Figma 未指定，必须向用户询问。
5. 首页已指定必须读取 `首页` Frame 和 `首页-切换` Frame。
6. 用户提供的 demo 只能作为效果参考，不得参考或照搬 demo 的实现方式，也不得覆盖 Figma 的视觉优先级。
7. 首页悬浮控件、屏幕边距和与屏幕边缘相关的位置必须按真实设备屏幕尺寸计算，单位使用 iOS point；以 Figma `iPhone Air` 屏幕范围 `420pt * 912pt` 为参考，横向按 `screenWidth / 420` 缩放，纵向按 `screenHeight / 912` 缩放。
8. 首页真实屏幕尺寸优先取 `UIScreen.main.bounds.size`，不得用滚动内容高度或普通容器高度替代真实屏幕高度。
9. 当前首页悬浮控件基准值：右上切换按钮 `44pt * 44pt`，距右 `20pt`、距上 `52pt`；底部搜索框 `306pt * 50pt`，右下添加按钮 `50pt * 50pt`，两者间距 `10pt`，底部整体左右边距 `27pt`，距真实屏幕底部 `27pt`。
10. 首页右上切换按钮的尺寸和上/右边距必须与详情页圆形按钮一致。
11. 画廊页顶部专辑区域、渐变阴影背景、三列卡片尺寸和标题字体必须按 `Frame 8` 记录的设计值实现。

## 7. 性能要求

1. 视频缩略图生成不得阻塞主线程。
2. 视频列表滚动必须保持流畅。
3. 播放器数量必须受控，避免多个视频同时占用大量资源。
4. 大视频文件读取必须考虑内存峰值。
5. 不得在滚动路径中执行高频日志、重计算或磁盘写入。
6. 首页纯色底动态取色、视频渐隐和渐变透明效果不得阻塞滚动主路径。
7. 视频取色应考虑缓存、异步计算和失败兜底色，具体算法实现前需结合 demo、Figma 和性能验证。
8. 画廊缩略图生成必须异步执行并缓存，不能阻塞滚动主路径。

## 8. 可测试性要求

1. 摘要规则应设计为可单元测试的纯逻辑。
2. 数据存储服务应可替换，以便测试。
3. 播放策略应尽量与具体 View 解耦。
4. 权限和失败状态应可模拟。

## 9. 禁止事项

1. 未经确认实现账号、云同步、社交分享、滤镜、剪辑、配乐等扩展功能。
2. 未读取 Figma 就实现正式 UI。
3. 删除用户系统相册中的原视频。
4. 使用私有 API。
5. 把旧项目 SimpleMemo 的规则当成 vimember 规则。
6. 未经用户要求提前实现第一版之外的分类 UI。
