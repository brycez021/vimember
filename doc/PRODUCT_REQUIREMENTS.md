# vimember Product Requirements

> 本文件承接原 `AGENTS.md` 中不必每轮完整加载的产品规格。做产品行为、流程或数据相关改动时读这里。

## 1. 项目定位

**产品名：** vimember

**一句话定位：** 一个 iOS 视频日记 App，用户从系统相册导入视频，为视频配上一段文字，然后用首页列表、画廊和详情页回看这些视频记忆。

当前主要工作是继续按 Figma 和用户截图精修交互细节，尤其是首页长按 Context Menu preview 视觉、专辑体验和后续数据模型。

## 2. 参考资料边界

项目内 `指导文件参考/` 文件夹保存的是另一个 iOS 项目的指导性文件，仅作为文档结构、协作方式、风险意识的参考。

1. 不得照搬旧项目的产品语义、页面结构或代码路径。
2. 不得把旧项目的“照片记忆”“回忆/相册”“瀑布流”等规则当成 vimember 的规则。
3. vimember 的实际规则以 `AGENTS.md`、本文件、用户最新要求和用户指定读取的 Figma 内容为准。
4. 如果旧参考文件与 vimember 要求冲突，必须忽略旧参考文件。

## 3. 视频导入与编辑

1. 用户可以从 iOS 系统相册导入视频，并给导入视频添加文字。
2. 添加文字后完成编辑，形成一条视频日记。
3. 导入视频后必须进入编辑页。
4. 首页右下角加号点击后进入视频选择页面。
5. 视频选择页面视觉来源为 Figma `选择视频` Frame。
6. 视频选择页面中所有视频不管原始横竖比例，都裁剪成正方形展示。
7. 点击某个视频后显示 Figma 中绘制的高亮标记和小对号。
8. 视频选择页左上角返回首页；选中视频后点击右上角对号进入下一步。
9. 选中视频后点击右上角对号，必须先进入视频预览页，而不是先进入添加文字页。
10. 视频预览页视觉来源为 Figma `添加-视频页` Frame。
11. 视频预览页只展示刚才选中的一条视频，视频自动播放。
12. 视频预览页不管横屏还是竖屏，视频都居中显示，并在视频上边缘和下边缘使用与横屏详情页相同思路的融合效果融入动态取色背景。
13. 视频预览页背景颜色逻辑和首页视频背景颜色逻辑一致：动态取色视频底色，视频边缘与背景融合。
14. 视频预览页底部有向下箭头；点击后页面向下滚动到添加文字页。
15. 添加文字页视觉来源为 Figma `添加-文字页` Frame。
16. 添加文字页左上角返回视频选择页；右上角确定完成加视频流程并回到首页。
17. 添加文字页上方有向上箭头；点击后页面向上滚动回视频预览页。
18. 添加文字页背景颜色必须与视频预览页下方纯色背景一致，使用选中视频的动态取色底色。
19. 添加文字页正文不设固定显示高度，内容超出屏幕后通过页面滚动查看。
20. 支持后续再次编辑文字；当前已实现从详情页和首页长按菜单进入添加文字/视频编辑态。
21. 添加文字页 title 和正文输入必须保持键盘稳定，不得输入一个字符后自动收起键盘。
22. 添加视频页和添加文字页顶部按钮高度必须与其他页面顶部 Liquid Glass 控件保持一致。
23. 当前需求只描述“视频 + 文字”的配对，不包含滤镜、剪辑、变速、配乐、贴纸等视频编辑能力，除非用户后续明确要求。

## 4. 首页视图

1. 首页展示所有已加入的视频日记，展示方式为上下排列。
2. 每条内容必须把视频和它搭配的文字放在一起。
3. 首页只展示文字摘要，不展示全文；点击内容进入详情视图。
4. 用户上下滑动首页时，视频不动；一旦用户停止滑动，当前屏幕上最主要的一条可见视频需要立刻开始播放。
5. 首页同一时间只播放最主要的一条视频，不同时播放多条视频。
6. Figma 中名为 `首页` 的 Frame 是首页正式 UI 的来源。该 Frame 内存在上下超出屏幕范围的内容，并包含屏幕范围标识；实现时必须理解屏幕范围与滚动内容的关系。
7. 首页必须适配不同尺寸的 iPhone，不得只按某一个 Figma 画布尺寸硬编码布局。
8. 首页视频展示方式参考用户准备的 demo 中“文稿/视频”效果，但只参考效果，不参考 demo 的实现方式。
9. 每个视频需要有一块取色视频纯色底。竖屏状态纯色底与视频同高，不向下超出视频高度；横屏状态纯色底高度大于视频高度，并向下超出视频下边界。
10. 视频下方需要叠加从上到下逐渐增强的模糊和透明度，让视频与纯色底自然融合，不能出现清晰视频、模糊层或纯色底之间的明显分界线。
11. 纯色底颜色需要实时取自视频底部融合参考区域的颜色。
12. 首页文字区域包含标题、日期、横线和正文。
13. 首页正文最多显示两行；超过两行时只显示两行，全文仍在详情页展示。
14. 首页搜索入口当前隐藏，相关代码可以保留但不得显示；是否恢复搜索后续再确认。
15. 首页右下角圆形按钮用于添加新内容；当前尺寸为 `58pt` 基准，距右/底均为 `28pt` 基准，并在 iOS 26 及以上使用原生 `.glassEffect(.regular.interactive(), in: Circle())`。
16. 首页右上角在 iOS 26 及以上为原生 Liquid Glass segmented display mode toggle，控制单栏 timeline 与三列 gallery/grid 模式。
17. 日期显示方式切换规则用户后续再提供，当前不得自行实现具体规则。
18. 首页视频按时间倒序排列，越新的视频越靠上；刚打开首页时显示最新视频，最上面视频卡片的上边界必须与屏幕上边界对齐。
19. 首页单栏和三列模式的视频卡片支持长按系统 Context Menu，菜单项为 Delete / Share / Edit；Delete 必须先弹确认，Share 先分享视频文件 URL，Edit 打开现有编辑流程。
20. 首页长按菜单当前采用 `UIContextMenuInteraction` + `UIContextMenuConfiguration` + `UIMenu` / `UIAction`，不要用自绘菜单、SwiftUI overlay、LongPressGesture 或 zIndex 修补来替代系统菜单。

## 5. 画廊视图

1. 画廊视图展示已经加入的视频日记，只展示文字摘要，不展示全文。
2. 点击画廊中的内容可以进入详情视图。
3. 画廊视图视觉来源为 Figma `Frame 8`，节点 `158:550`。
4. 画廊顶部有 `Albums` 专辑栏，下面有 `All Videos` 视频网格。
5. 专辑栏下方有一层从白色到浅灰的渐变阴影背景。
6. 专辑封面当前为 `70pt` 基准的圆角方形卡片，外圆角 `10pt`，缩略图为轻微 inset 的圆角矩形，不再使用圆形专辑封面。
7. 专辑圆角方形卡片一字排开，可左右滑动；选中某个专辑后，其他专辑轻微灰化，不能变成彻底黑白。
8. 第一个专辑方形卡片为添加新专辑入口；点击后从 `70pt / 10pt` 圆角方形 morph 到添加专辑卡片，动画起点不得跳动。
9. 当前已有轻量专辑原型：可创建专辑、选择视频加入专辑、进入某个专辑筛选视频、通过左滑手势退出专辑选择。正式持久化专辑数据模型和完整专辑详情页仍待确认。
10. 视频区域按 Figma 三列卡片排列，用户可向下滑动查看更多视频卡片；卡片左右缝隙和上下缝隙必须一致。
11. 每个视频卡片保留视频中间正方形画面，下面垫动态取色纯色背景。
12. 视频卡片底部需要像横屏详情页下边缘一样丝滑融入纯色背景。
13. 视频卡片下方显示两行标题；标题过长必须省略。
14. 视频卡片圆角为 `3pt`；贴近屏幕边缘的外侧角保持直角。

## 6. 详情视图

1. 详情视图展示完整视频和完整文字。
2. 详情视图中的视频需要自动播放并反复循环播放。
3. 详情视图左上角为返回按钮；右上角在 iOS 26 及以上为单个会 morph 的原生 Liquid Glass 按钮：文字折叠态显示删除圆按钮，文字展开后 morph 成编辑跑道圆。
4. 点击删除必须先弹出确认，再彻底删除。
5. 删除只删除 App 本地数据库记录和 App 沙盒里的视频文件，不删除系统相册原视频。
6. 点击编辑进入添加文字/视频编辑态，编辑页面继续作为全屏浮层显示。
7. 详情页文字卡片初始覆盖在视频底部；向上滑动时使用同一块 persistent 底部毛玻璃面板连续上移/形变，不得用两个 View 或普通 sheet 做 if/else 切换。
8. 在屏幕靠上位置明显向下滑动时，文字页收回到原本位置。
9. 详情页文字展开后的背景颜色必须沿用视频底部动态取色底色。
10. 详情页横屏视频在屏幕中视觉居中，视频上边缘和下边缘都需要丝滑融入动态取色背景。
11. 详情页文字上滑过程中，背景视频同步做较小幅度视差上移，并随 `panelProgress` 逐渐变模糊；文字展开到全文状态后视频自动暂停，收回后继续播放。
12. 详情页原横线已变成播放进度条：底层 0.5pt 横线位置不变，上方叠 3pt 白色进度条；进度条可拖动 seek，且必须跟随文字层上滑/下滑。
13. 详情页视频当前应有声音，使用 `AVAudioSession` playback/moviePlayback；首页和其他预览视频仍默认静音。

## 7. 已确认的产品与技术决策

1. 视频导入后复制到 App 本地沙盒，App 展示和播放使用自己的本地视频文件。
2. App 可以保存原相册视频的来源标识作为记录或未来关联，但不能依赖系统相册原视频作为唯一播放来源。
3. 文字保存在 App 本地数据库。
4. 摘要规则为展示正文前面固定字数的一部分；具体字数、行数和截断样式后续由用户确认。
5. 首页停止滚动后只播放当前屏幕中最主要的一条视频；“最主要”的判定细节在实现前结合 Figma 和用户确认。
6. 导入视频后必须进入编辑页。
7. 支持再次编辑；当前入口为详情页右上跑道圆编辑按钮。
8. 支持删除视频日记；删除只删除 App 本地数据库记录和 App 沙盒里的视频文件，任何时候都不删除系统相册原视频。
9. iCloud、账号、同步、备份、导出等能力后续再说，MVP 不提前实现。
10. 当前工程 deployment target 为 iOS 17.0，使用当前 App Store 接受的最新 iOS SDK 构建；iOS 26 及以上继续采用原生 Liquid Glass API，iOS 17-25 只做官方公开 API 的兼容 fallback。
11. 当前画廊页和首页顶部已加入专辑栏原型，但正式专辑持久化数据模型、完整专辑详情流程仍待用户后续确认。
12. iOS 26 及以上的可点击 Liquid Glass 按钮统一使用 `Button` + 固定尺寸内容 + `.glassEffect(.regular.interactive(), in:)` + `.buttonStyle(.plain)`；iOS 17-25 使用兼容 material fallback，不要恢复旧的自定义半透明白底、stroke、shadow、高光来替代 26 原生按钮玻璃。

## 8. 核心行为不可破坏

1. 视频日记必须由“视频 + 文字”组成。
2. 首页和画廊都只展示摘要。
3. 详情页必须展示全文。
4. 首页滚动时视频不播放或不运动；滚动停止后，只播放最主要的一条可见视频。
5. 详情页视频自动循环播放。
6. 正式 UI 必须以用户指定读取的 Figma 内容为准。
7. 删除视频日记时，任何时候都不能删除系统相册原视频。
8. 首页 `首页` Frame 和 `首页-切换` Frame 的视觉意图不得被通用模板替代。
9. 首页视频纯色底、横竖屏差异化底色高度、渐进透明融合、动态取色视频底色、标题/日期/横线/两行正文结构属于首页已确认体验。
